# 2.1 — Server-Side Environment

> How to hold onto secrets without ever leaking them to the browser.

## Why this matters

Your SvelteKit app has two runtimes: the server and the browser. Secrets — the Supabase service-role key, the Stripe secret key — must **never** reach the browser. SvelteKit gives us a clean convention for this through its `$env/static/*` and `$env/dynamic/*` modules. Learn it once; use it forever.

## The Principal Engineer lens

Four rules we'll follow for the rest of the course:

1. **Public env vars start with `PUBLIC_`.** Anything else is server-only. SvelteKit will refuse to let you import a non-public var into browser code — a compile-time guarantee, not a convention.
2. **Validate env at startup, not at use.** If `SUPABASE_URL` is missing, we want a loud error on `pnpm dev`, not a 500 in production at 3 AM.
3. **Commit `.env.example`, never `.env`.** Example is documentation; real values are secrets.
4. **Never access `process.env` directly.** Use `$env/static/private` (baked at build time, tree-shakeable) or `$env/dynamic/private` (read at runtime, for values that change per environment).

## Step 1 — Create your `.env`

In `app/`:

```bash
cp .env.example .env
```

Then paste in your local Supabase values. You got them from `pnpm supabase:status` in Lesson 1.2 — they look like this:

```bash
# app/.env

# ─── Supabase (local) ────────────────────────────────────────────────────────
PUBLIC_SUPABASE_URL=http://127.0.0.1:54321
PUBLIC_SUPABASE_ANON_KEY=eyJhbGciOi...        # the anon key from supabase status
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...        # the service_role key

# ─── Stripe (we'll fill these in Module 5) ───────────────────────────────────
STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
PUBLIC_STRIPE_PUBLISHABLE_KEY=

# ─── App ─────────────────────────────────────────────────────────────────────
PUBLIC_APP_URL=http://localhost:5173
```

> The anon key is public-safe: it's subject to RLS. The service-role key bypasses RLS — treat it like a root password.

## Step 2 — Create `.env.example`

This is committed; never put real values in it.

```bash
# app/.env.example
PUBLIC_SUPABASE_URL=
PUBLIC_SUPABASE_ANON_KEY=
SUPABASE_SERVICE_ROLE_KEY=

STRIPE_SECRET_KEY=
STRIPE_WEBHOOK_SECRET=
PUBLIC_STRIPE_PUBLISHABLE_KEY=

PUBLIC_APP_URL=http://localhost:5173
```

## Step 3 — Make sure `.env` is gitignored

Check `.gitignore` at the repo root. It should already have:

```
.env
.env.*
!.env.example
```

The `!` excludes `.env.example` from the gitignore — that one *does* get committed.

Run `git status` — `.env` must **not** appear. If it does, add it to `.gitignore` before committing anything.

## Step 4 — Understand the four `$env` flavors

SvelteKit exposes env vars through four modules:

| Module | Read at | Scope | Use for |
|---|---|---|---|
| `$env/static/private` | build time | server | Secrets that don't change per deploy |
| `$env/static/public` | build time | anywhere | Public config baked into the bundle |
| `$env/dynamic/private` | runtime | server | Secrets that might differ per environment/region |
| `$env/dynamic/public` | runtime | anywhere | Public config read at runtime |

Principal Engineer rule of thumb: **prefer `static` over `dynamic`.** Static is faster (tree-shaken at build) and safer (the value is locked when you deploy). Use `dynamic` only when you truly need a value to change at runtime without a rebuild — which, in our app, is basically never.

## Step 5 — Write a typed env module

Let's centralize env reads into a single file. Create `src/lib/server/env.ts`:

```ts
// src/lib/server/env.ts
import {
	PUBLIC_SUPABASE_URL,
	PUBLIC_SUPABASE_ANON_KEY,
	PUBLIC_APP_URL
} from '$env/static/public';
import {
	SUPABASE_SERVICE_ROLE_KEY,
	STRIPE_SECRET_KEY,
	STRIPE_WEBHOOK_SECRET
} from '$env/static/private';

function required(name: string, value: string | undefined): string {
	if (!value || value.length === 0) {
		throw new Error(`Missing required env var: ${name}`);
	}
	return value;
}

export const env = {
	PUBLIC_SUPABASE_URL: required('PUBLIC_SUPABASE_URL', PUBLIC_SUPABASE_URL),
	PUBLIC_SUPABASE_ANON_KEY: required('PUBLIC_SUPABASE_ANON_KEY', PUBLIC_SUPABASE_ANON_KEY),
	PUBLIC_APP_URL: required('PUBLIC_APP_URL', PUBLIC_APP_URL),
	SUPABASE_SERVICE_ROLE_KEY: required('SUPABASE_SERVICE_ROLE_KEY', SUPABASE_SERVICE_ROLE_KEY),
	STRIPE_SECRET_KEY: required('STRIPE_SECRET_KEY', STRIPE_SECRET_KEY),
	STRIPE_WEBHOOK_SECRET: required('STRIPE_WEBHOOK_SECRET', STRIPE_WEBHOOK_SECRET)
} as const;
```

> **Why do we check values here when SvelteKit already fails if the import is missing?** Because `static` will tolerate empty strings. A `""` from your `.env` will happily import — and then silently break at runtime. The explicit `required()` check converts "silently broken" into "loud error at startup".

## Step 6 — Separate `server/` folder matters

Notice the path: `src/lib/server/env.ts`. SvelteKit enforces a rule: **anything under `$lib/server/` cannot be imported into browser code.** If you try, the build fails. That's another free test.

We'll use `$lib/server/` for:

- Env (this file)
- Supabase admin client
- Stripe SDK client
- Tier/entitlement logic
- Any function that touches secrets

## Step 7 — Test it

Run the dev server:

```bash
pnpm dev
```

It should start without errors. Now temporarily break something: open `.env`, delete the value after `PUBLIC_SUPABASE_URL=`, save, and **restart** `pnpm dev`. You should see:

```
Missing required env var: PUBLIC_SUPABASE_URL
```

Good — that's exactly the loud failure we want. Restore the value.

## Verify

- `.env` is ignored by git (`git status` should never show it).
- `.env.example` is committed and has no real values.
- `src/lib/server/env.ts` exports a typed `env` object.
- `pnpm dev` starts cleanly with all values present.

## Common traps

- **Adding `PUBLIC_STRIPE_SECRET_KEY` by mistake.** The `PUBLIC_` prefix means "ship me to the browser." Stripe secret keys go through `$env/static/private` without the prefix.
- **Reading env inside a `+page.svelte`.** Only `PUBLIC_*` vars can live there, and even then we prefer to read them in `+layout.server.ts` or a remote function and pass values down.
- **Using `process.env.FOO` directly.** Works, but bypasses SvelteKit's public/private protection. Don't.

## Recap

You have a typed, validated env layer. Every secret has a single place it's read. The browser bundle literally cannot import anything from `$lib/server/`. That's the foundation we'll build the Supabase + Stripe clients on.
