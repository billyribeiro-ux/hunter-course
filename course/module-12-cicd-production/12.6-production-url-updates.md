# 12.6 — Production URL Updates

> The loose ends: domain, redirect URLs, CORS, OAuth allowlists, `PUBLIC_APP_URL`, `robots.txt`, the health endpoint. One checklist before you announce.

## Why this matters

Every prior lesson in Module 12 set up the machinery: Supabase, Vercel, GitHub Actions, Stripe live mode. None of that helps if the machinery points at the wrong URL.

This is the "I shipped but email confirmations go to `localhost:5173`" lesson. It's mundane. It's also the single most common cause of "the deploy succeeded but nothing works."

## The Principal Engineer lens

**URLs are a cross-cutting concern.** Half a dozen systems need to know what "production" means. Forgetting to update *one* of them means customers hit a deploy that mostly works — confirmation emails 404, Stripe redirects break, OAuth logins bounce. Every failure mode is independent and invisible until a real user stumbles into it.

Corollary: **have one place that says "production URL is `X`."** That's the `PUBLIC_APP_URL` env var. Everything else — Stripe success URLs, Supabase redirect URLs, email templates — derives from it or is set to match it. If you change domains later, you grep for the value, not thirty ad-hoc references.

## Step 1 — Buy a domain

Pick a registrar you trust (Namecheap, Cloudflare, Porkbun). For Contactly we'll use `contactly.app`.

- Turn on WHOIS privacy. You're a business now; hiding your home address costs $0.
- Turn on registrar lock. Prevents domain hijacking.
- Set a reminder 60 days before expiry — lapsed domains auction fast.

Cost: $10–$20/year. Negligible.

## Step 2 — Attach the domain in Vercel

Vercel → Project → **Settings → Domains → Add**:

1. Enter `contactly.app`. Click Add.
2. Vercel shows you two DNS records to create at your registrar:
   - `A` record on `@` pointing to `76.76.21.21`.
   - `CNAME` on `www` pointing to `cname.vercel-dns.com`.
3. Add those records at your registrar. TTL: 300 or lower so propagation is fast.
4. Wait 2–10 minutes. Vercel auto-provisions TLS via Let's Encrypt once DNS resolves.

Once green, `https://contactly.app` should serve your app. `https://www.contactly.app` should redirect to the apex (Vercel's default).

## Step 3 — Update `PUBLIC_APP_URL`

Vercel → Settings → Environment Variables → edit `PUBLIC_APP_URL`:

- Production scope: `https://contactly.app`.
- Preview scope: keep as-is (per-deploy or stable-preview logic from 12.3).

Redeploy. Verify by viewing source on `https://contactly.app/pricing` — the checkout form action should reference `contactly.app`, not `contactly-xxx.vercel.app`.

## Step 4 — Update Supabase redirect URLs

Supabase dashboard → **Authentication → URL Configuration**:

- **Site URL**: `https://contactly.app`.
- **Additional Redirect URLs** (one per line):
  - `https://contactly.app/**`
  - `https://contactly-preview.vercel.app/**` (for preview deploys)
  - `http://localhost:5173/**` (for local dev against prod Supabase — rare but useful)

The `**` wildcard matches any path. Without it, Supabase will reject the callback URL and confirmation emails will land users on a blank error page.

Save. Send yourself a test signup from prod. Click the confirmation link. You should land on `/app` (or wherever the redirect goes) cleanly.

## Step 5 — Update Supabase email templates

Supabase → **Authentication → Email Templates**. Four templates: Confirm signup, Invite, Magic link, Reset password.

Each template has `{{ .ConfirmationURL }}` tokens that use the Site URL from Step 4. You shouldn't need to edit URLs — but do edit the *body* for brand:

- Replace "Supabase" with "Contactly" in the from-name.
- Add a one-line explanation so it doesn't look like spam: *"You signed up for Contactly at contactly.app. Click below to confirm."*
- Keep the link text plain ("Confirm your email") — fancy HTML buttons often get caught by Gmail's promotions tab.

The Supabase-default sender is `noreply@mail.app.supabase.io`. For a real launch, upgrade to a custom SMTP provider (Resend, Postmark, SendGrid) — covered briefly in Step 7.

## Step 6 — Update Stripe redirect URLs

Stripe Checkout needs success / cancel URLs. These are already passed at session creation (Module 9.1), but they derive from `PUBLIC_APP_URL`. Since we updated that in Step 3, the URLs will be correct on the next deploy.

Double-check by creating a new Checkout session on prod:

1. Go to `https://contactly.app/pricing`, click Upgrade.
2. On the Stripe-hosted Checkout, note the `return_url` query param or cancel URL in the browser's address bar — should be `contactly.app/...`.

Also update the Customer Portal return URL in Stripe → **Settings → Billing → Customer Portal**:

- **Default return URL**: `https://contactly.app/app/account`.

Without this, the "back to app" button on the portal goes nowhere useful.

## Step 7 — Custom SMTP (optional but recommended)

Supabase's free-tier email sender is rate-limited and will land in spam more often than not. For a launch, switch to a dedicated provider.

We recommend **Resend** — three minutes to set up, generous free tier, designed for transactional email.

1. Sign up at resend.com. Verify your sending domain (`contactly.app`) via DNS TXT/DKIM records at your registrar.
2. Create an API key.
3. Supabase → **Authentication → SMTP Settings**:
   - Host: `smtp.resend.com`.
   - Port: `465` (or `587` for STARTTLS).
   - Username: `resend`.
   - Password: your Resend API key.
   - Sender email: `noreply@contactly.app`.
   - Sender name: `Contactly`.
4. Save. Send a test signup. Confirmation email should come from `noreply@contactly.app` now.

Bonus: Resend's dashboard shows delivery + bounce stats, so you can see in real time whether emails are landing.

## Step 8 — Add the health endpoint

Module 12.4's smoke test hits `/api/health`. Time to implement it.

```ts
// src/routes/api/health/+server.ts
import { json } from '@sveltejs/kit';
import { getAdminClient } from '$lib/server/supabase-admin';

export const GET = async () => {
	const started = Date.now();
	const admin = getAdminClient();

	const { error } = await admin
		.from('profiles')
		.select('id', { head: true, count: 'exact' })
		.limit(1);

	const dbMs = Date.now() - started;

	if (error) {
		return json({ ok: false, error: 'db', dbMs }, { status: 503 });
	}

	return json({ ok: true, dbMs });
};
```

- `head: true` means "don't return rows, just check reachability."
- Response is JSON so you can `curl | jq` for monitoring.
- 503 on DB error means monitors trip correctly (not a generic 500).

Verify: `curl https://contactly.app/api/health` → `{"ok":true,"dbMs":NN}`.

## Step 9 — `robots.txt` and search indexing

By default SvelteKit serves no `robots.txt`, which means search engines crawl everything — including `/app/*` (auth-gated). Most routes will 302 to `/login`, bloating your crawl budget with nothing useful.

Create `src/routes/robots.txt/+server.ts`:

```ts
export const GET = () => {
	const body = `User-agent: *
Allow: /
Disallow: /app/
Disallow: /api/

Sitemap: https://contactly.app/sitemap.xml
`;
	return new Response(body, {
		headers: { 'content-type': 'text/plain' }
	});
};
```

If you haven't built a sitemap yet, skip the Sitemap line. Don't fake it.

## Step 10 — Open Graph + favicon

Every URL shared on social media renders a preview. Defaults are ugly or absent. Fix both:

- `static/favicon.svg` — a 32x32 SVG of your logo. SVG scales cleanly across every device.
- `static/og-image.png` — 1200x630 PNG with your wordmark and tagline. Use Figma or Canva; don't overthink.
- In `src/app.html` add to `<head>`:

```html
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
<meta property="og:site_name" content="Contactly" />
<meta property="og:image" content="https://contactly.app/og-image.png" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta name="twitter:card" content="summary_large_image" />
```

Verify by pasting `https://contactly.app` into Slack or Twitter's card validator. You should see the image preview immediately.

## Step 11 — One last prod smoke

Sign out. Open an incognito window. Now walk through the full flow on `contactly.app`:

1. Sign up with a fresh email → confirmation email arrives from `noreply@contactly.app`.
2. Click the link → lands on `/app` without error.
3. Go to `/pricing` → prices render, Monthly/Yearly toggle works.
4. Click Upgrade to Plus → Stripe Checkout opens, branded "Contactly," success URL reads `contactly.app/...`.
5. Use a real card → redirected to `/billing/success` → `stripe_subscriptions` row appears in prod Supabase.
6. Go to `/app/account` → see subscription details.
7. Click Manage billing → Stripe Portal opens, return URL works.
8. Refund yourself via Stripe dashboard → subscription row updates within seconds (webhook).
9. Sign out → `/app` redirects to `/login`.

Every click is another chance to catch a URL mismatch. If any step misroutes, the env var or redirect URL in question is wrong. Fix and redeploy.

## Verify

- `https://contactly.app` serves the app with a valid TLS cert.
- A fresh signup receives a confirmation email from `noreply@contactly.app` (or the Supabase default if you skipped Step 7) and the link lands on `/app`.
- Stripe Checkout success and cancel URLs point at `contactly.app`.
- `/api/health` returns `{"ok":true}`.
- `robots.txt` disallows `/app/` and `/api/`.
- Sharing `https://contactly.app` on Slack renders an image preview.
- The GitHub Actions smoke step from 12.4 passes on the next `main` push.

## Common traps

- **Supabase Site URL left at `localhost:5173`.** Every confirmation link routes users to a dead localhost address. Check Step 4 first if "my confirmation emails don't work."
- **`PUBLIC_APP_URL` inconsistent across environments.** Production has `https://contactly.app` but the code still builds the URL from `VERCEL_URL`, which on prod is the ugly `contactly-xxx.vercel.app`. Always prefer `PUBLIC_APP_URL` in Checkout/Portal URLs.
- **DNS propagation isn't instant.** If `https://contactly.app` 404s immediately after adding the domain, wait 10 minutes. Use `dig contactly.app` or dnschecker.org to verify.
- **Forgetting to redeploy after changing env vars.** Vercel reads env vars at build time. An env var change needs a redeploy to take effect; you'll see the old value in shipped JS otherwise.
- **Adding `www.contactly.app` without a redirect.** Vercel can handle both, but you want one canonical — pick apex (`contactly.app`) and redirect `www` to it. Otherwise Google indexes both and split link equity.
- **Skipping the health endpoint.** The GitHub Actions smoke test from 12.4 needs it. Without it, CI reports green on a broken deploy.

## Recap

The domain is live. Supabase, Stripe, and the app all agree on what `https://contactly.app` means. Emails are branded. Health check passes. Social previews render. Production is real.

Module 12 is complete. You now have a pipeline that goes from `git push` → green CI → atomic Vercel deploy → migrated DB → smoke-tested health check — and a production environment wired to match. From here, every subsequent feature follows the same path.
