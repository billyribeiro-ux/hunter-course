# 12.5 — Stripe & Supabase in Production

> Flip the switches that turn a demo into a business: live-mode keys, production webhook endpoint, seeded prices.

## Why this matters

Everything up to now has used Stripe test mode and local or newly-provisioned Supabase. For real money to flow, we need to:

1. Activate Stripe for live payments.
2. Create the production webhook endpoint.
3. Seed the production Stripe account with products + prices.
4. Point the production app at the live credentials.

None of this is technically complex. It's *operationally* unforgiving — a mis-scoped env var here is a support ticket there. This lesson is a checklist.

## The Principal Engineer lens

**Production rollout is a drill, not a reveal.** Run through the checklist once on paper. Then once with someone watching. Then do it for real with the watcher reviewing each step. You will never regret the practice runs.

Corollary: **first real transaction = first real bug report.** Plan to be available for 48 hours after enabling live mode. Bugs that never appeared in test mode (declined cards, 3DS flows, international fees) will surface in the first week of real use.

## Step 1 — Activate Stripe for live payments

In Stripe dashboard → **Activate payments**. You'll be asked for:

- Business details: name, address, country.
- Tax details: EIN / VAT number if applicable.
- Bank account for payouts.
- A representative's personal info (KYC).

Approval is usually same-day. Save the confirmation email.

Once approved, toggle the dashboard to **Live mode** (top-right) to see a blank live environment. This is good — you haven't created anything yet.

## Step 2 — Get live-mode API keys

Still in live mode: **Developers → API keys**. Copy:

- **Publishable key** (`pk_live_...`) → Vercel `PUBLIC_STRIPE_PUBLISHABLE_KEY` (Production scope only).
- **Secret key** (`sk_live_...`) — click "Reveal." Copy once, never store in a file. Paste into Vercel `STRIPE_SECRET_KEY` (Production scope only).

Rotate these keys at any time from the same page. If they ever leak, rotate immediately and update Vercel.

## Step 3 — Seed live-mode Stripe

Run the seed script — but with live credentials this one time.

```bash
cd app
STRIPE_SECRET_KEY=sk_live_xxx pnpm seed:stripe
```

Expected output: "created product Plus," "created product Pro," four "created price" lines. You are now creating real billable products.

Double-check in the dashboard → **Products** (in live mode). You should see:

- Plus — 2 active prices ($10/month, $96/year), each with the right lookup key.
- Pro — 2 active prices ($20/month, $192/year).

If anything's missing or wrong, archive it and re-run the seed. The script is idempotent.

## Step 4 — Create the production webhook endpoint

In Stripe dashboard → **Developers → Webhooks → Add endpoint**.

- **Endpoint URL**: `https://contactly.app/api/webhooks/stripe`.
- **Listen to**: pick the events Contactly handles:
  - `checkout.session.completed`
  - `customer.subscription.created`
  - `customer.subscription.updated`
  - `customer.subscription.deleted`
  - `customer.subscription.trial_will_end`
  - `invoice.paid`
  - `invoice.payment_failed`
  - `customer.created`
- **API version**: `2026-03-25.dahlia` (match the pinned version in `src/lib/server/stripe.ts`).

Click **Add endpoint**. Stripe generates a signing secret like `whsec_abcdef...`. Copy it. Paste it into Vercel `STRIPE_WEBHOOK_SECRET` (Production scope only).

## Step 5 — Test the production webhook

Still in the endpoint page, click **Send test webhook**. Pick `checkout.session.completed`. Send.

In a separate tab, Vercel → Deployments → latest prod deploy → **Functions** tab → pick `api/webhooks/stripe`. Logs should show a line like `[stripe webhook] checkout.session.completed evt_1Pz...`.

If you see it: signature verification passed, the endpoint is live, our handler ran. If you see a 400 in Stripe's attempt list: the signing secret in Vercel doesn't match the one Stripe shows. Re-copy + redeploy.

## Step 6 — Configure Customer Portal (live mode)

Module 9.7 walked through this in test mode. Repeat in live:

- **Billing → Customer Portal → Configure**.
- Enable plan change, cancellation, payment method update, invoice history.
- Add Plus and Pro to the "Products" section.
- Save.

Test via the "Test live portal" link — even in live mode, this gives you a preview without a real customer.

## Step 7 — Set the webhook endpoint for preview deploys

Each Vercel preview has its own URL. You don't want to create a webhook endpoint per preview — instead, use `stripe listen --forward-to ...` as needed during dev, or (for a longer-lived preview environment):

- Create a *single* webhook endpoint in **test mode** pointing at a stable preview URL like `contactly-preview.vercel.app/api/webhooks/stripe`.
- Put its signing secret into Vercel `STRIPE_WEBHOOK_SECRET` (Preview scope).

This is okay because previews only receive test-mode events.

## Step 8 — Supabase production smoke test

Log into `https://contactly.app` with a real email + password.

- Sign up → you should receive a confirmation email (if you turned on Confirm Email in 12.2).
- Click confirmation → you're redirected into `/app`.
- Add a contact → stored.
- Go to `/pricing` → prices show live amounts (from the live-mode seed).
- Click **Upgrade to Plus** → redirected to Stripe Checkout with *real* fields.
- Enter a real test card *first* — wait, no. Use your actual card for $10. Or use Stripe's `4242 4242 4242 4242` — *it will fail* in live mode (test cards only work in test mode). Use your real card.

**Side note on the first real transaction.** Charge yourself. Refund yourself immediately from the Stripe dashboard. You'll have:

- Verified the full flow end-to-end with real money.
- A receipt in your email to inspect.
- A clean $0 net outcome.

## Step 9 — Dunning email settings

Stripe → **Settings → Customer emails**. Enable:

- Payment succeeded (receipts).
- Payment failed (retry notifications).
- Upcoming invoice (1 day before renewal).

These are the emails your customers will get from Stripe directly. They're on Stripe's domain and branded by default; customise the header logo + colour for your brand.

## Step 10 — The dunning + retry policy

Stripe → **Settings → Subscriptions → Retries**. Default (3 retries over 3 weeks) is sane for Contactly. Consider tightening to 2 retries over 1 week if you'd rather cancel dead-card subs sooner; defaults are the right starting point.

## Step 11 — Rotate the old `.env` on your laptop

You've been using local `.env` for test-mode keys. Make sure it still has only test keys, never live. A helpful safety: grep `.env` for `_live_`:

```bash
grep "_live_" app/.env   # should return nothing
```

If anything matches, delete it immediately. Live keys on a laptop are one disk-level compromise away from a disaster.

## Verify

- Vercel production env vars include `sk_live_...` and `pk_live_...`.
- Live-mode webhook endpoint exists and responds 200 to test sends.
- `/pricing` on `contactly.app` shows four prices pulled from live Stripe.
- One real-card test transaction ran through Checkout → webhook → `stripe_subscriptions` row appears in prod Supabase.
- The transaction was refunded; no unintended charge remains.

## Common traps

- **Using test keys in production Vercel env vars.** Payments succeed in the UI but silently fail to charge. Customers are angry weeks later. Always re-verify `PUBLIC_STRIPE_PUBLISHABLE_KEY` starts with `pk_live_` on production.
- **Skipping the real-card test transaction.** Test-mode and live-mode diverge more than you'd expect (3DS, international fees, bank quirks). Run a real charge before you announce.
- **Webhook endpoint pointing at a preview URL.** The preview URL of the moment you created it is not the one your production traffic hits. Always `https://contactly.app/api/webhooks/stripe` for prod.
- **Forgetting the `customer.created` event.** Without it, the user → Stripe customer mirror drifts. Subscribe to it even if you don't handle it today; the cost is near-zero.
- **Leaving the dashboard in live mode by accident.** Toggle back to test mode for day-to-day dev. An edit to "just test something" in live can create a real product or trigger a real email.

## Recap

Stripe is live. Webhooks are wired. Products and prices are seeded. One real transaction has proven the pipeline end-to-end. Production is ready. Final lesson: all the little URL and config loose ends that trip up first-time deploys.
