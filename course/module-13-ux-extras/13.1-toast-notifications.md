# 13.1 — Toast Notifications

> The quietest UX upgrade that makes every interaction feel polished. Built with Svelte 5 runes and a single global store.

## Why this matters

Click "Save." Nothing happens. Did it work? Most users refresh the page to find out. That refresh is a sign the UI lied — either by not responding, or by responding invisibly.

Toasts are the acknowledgement. Click Save → a small "Saved." appears bottom-right for 3 seconds → disappears. No friction, no modal, no page reload. The user's mental model stays intact.

This lesson builds the toast system Contactly will use everywhere: on contact saves, subscription changes, errors, undo prompts. One small component that pays for itself a hundred times.

## The Principal Engineer lens

**Toasts should tell the user what the system did, not what the system is doing.** "Saving…" is a spinner's job; "Saved." is a toast's job. Toasts confirm completed actions — successes, errors, warnings. Anything mid-flight belongs in a button's loading state.

Corollary: **every non-idempotent action should produce a toast.** If an action changes data and the user can't see the change on screen (contact added to a paginated list, subscription renewed, webhook processed), a toast is the confirmation. If the change *is* visible (contact row updates inline), a toast is redundant.

## Step 1 — The store

Create `src/lib/stores/toasts.svelte.ts`:

```ts
export type ToastKind = 'success' | 'error' | 'info';

export interface Toast {
	id: string;
	kind: ToastKind;
	message: string;
	timeoutMs: number;
}

function createToastStore() {
	let toasts = $state<Toast[]>([]);

	function push(kind: ToastKind, message: string, timeoutMs = 3500) {
		const id = crypto.randomUUID();
		toasts = [...toasts, { id, kind, message, timeoutMs }];

		if (timeoutMs > 0) {
			setTimeout(() => dismiss(id), timeoutMs);
		}
	}

	function dismiss(id: string) {
		toasts = toasts.filter((t) => t.id !== id);
	}

	return {
		get all() {
			return toasts;
		},
		success: (msg: string, ms?: number) => push('success', msg, ms),
		error: (msg: string, ms?: number) => push('error', msg, ms ?? 6000),
		info: (msg: string, ms?: number) => push('info', msg, ms),
		dismiss
	};
}

export const toasts = createToastStore();
```

Three reads worth calling out:

- **`.svelte.ts` file extension.** Svelte 5 runes (`$state`) only work in `.svelte` or `.svelte.ts` files. Plain `.ts` would silently fall through to ordinary variables — no reactivity.
- **Errors stay longer.** 3.5 s for success, 6 s for errors. If an action failed, the user deserves extra time to read *why*.
- **`crypto.randomUUID()` for IDs.** Keyed-each blocks need stable IDs or Svelte can't animate list changes cleanly.

## Step 2 — The component

Create `src/lib/components/Toaster.svelte`:

```svelte
<script lang="ts">
	import { toasts } from '$lib/stores/toasts.svelte.ts';
	import { fly } from 'svelte/transition';
</script>

<div class="toaster" aria-live="polite" aria-atomic="false">
	{#each toasts.all as toast (toast.id)}
		<div
			class="toast toast-{toast.kind}"
			role={toast.kind === 'error' ? 'alert' : 'status'}
			transition:fly={{ y: 16, duration: 200 }}
		>
			<span class="message">{toast.message}</span>
			<button
				class="dismiss"
				aria-label="Dismiss"
				onclick={() => toasts.dismiss(toast.id)}
			>
				×
			</button>
		</div>
	{/each}
</div>

<style>
	.toaster {
		position: fixed;
		bottom: 1.5rem;
		right: 1.5rem;
		display: flex;
		flex-direction: column;
		gap: 0.5rem;
		z-index: 9999;
		pointer-events: none;
	}
	.toast {
		pointer-events: auto;
		display: flex;
		align-items: center;
		gap: 0.75rem;
		padding: 0.75rem 1rem;
		border-radius: 0.5rem;
		box-shadow: 0 4px 12px rgb(0 0 0 / 0.12);
		font-size: 0.9rem;
		min-width: 16rem;
		max-width: 24rem;
	}
	.toast-success { background: #e6f4ea; color: #14532d; }
	.toast-error   { background: #fdecea; color: #7f1d1d; }
	.toast-info    { background: #e6f0fb; color: #1e3a8a; }
	.dismiss {
		background: transparent;
		border: 0;
		font-size: 1.25rem;
		cursor: pointer;
		color: inherit;
		line-height: 1;
	}
</style>
```

Details that matter:

- **`aria-live="polite"`** tells screen readers to announce new toasts without interrupting. For errors we override `role="alert"` (assertive) so critical messages aren't missed.
- **`pointer-events: none`** on the container lets clicks pass through the empty space; re-enabled on `.toast` so the × button works.
- **`fly` transition** with small `y: 16` — subtle enough to feel polished, not so much it feels like a full animation.

## Step 3 — Mount once in the root layout

`src/routes/+layout.svelte`:

```svelte
<script lang="ts">
	import type { Snippet } from 'svelte';
	import Toaster from '$lib/components/Toaster.svelte';
	let { children }: { children: Snippet } = $props();
</script>

{@render children()}
<Toaster />
```

Mounted at the layout root, the toaster survives every navigation. No need to include it per-page.

## Step 4 — Use it from anywhere

A contact create form after successful submit:

```svelte
<script lang="ts">
	import { toasts } from '$lib/stores/toasts.svelte.ts';
	import { createContact } from '$lib/remote/contacts.remote.ts';

	async function onSubmit(data: FormData) {
		const result = await createContact(data);
		if (result.ok) {
			toasts.success('Contact added.');
		} else {
			toasts.error(result.error);
		}
	}
</script>
```

Or from a server-form enhancer, after an HTTP 402 (entitlement denied) from Module 10.2:

```ts
if (response.status === 402) {
	toasts.error('Upgrade to add more contacts.');
}
```

Or as an undo prompt, giving the user 5 seconds to bail on a delete:

```ts
toasts.info('Contact deleted. [Undo]', 5000);
```

(Undo wiring is Module 13.2 territory.)

## Step 5 — Test it

Playwright, in `tests/toasts.spec.ts`:

```ts
import { test, expect } from '@playwright/test';

test('success toast on contact create', async ({ page }) => {
	await page.goto('/app');
	await page.getByRole('button', { name: 'New contact' }).click();
	await page.getByLabel('Name').fill('Ada');
	await page.getByRole('button', { name: 'Save' }).click();

	const toast = page.getByRole('status').filter({ hasText: 'Contact added.' });
	await expect(toast).toBeVisible();
	await expect(toast).toBeHidden({ timeout: 5000 });
});
```

The second expect waits for the toast to auto-dismiss. If the timeout is wrong (toast sticks forever, toast vanishes too fast), this test catches it.

## Verify

- Create a contact → "Contact added." appears bottom-right and disappears after 3.5 s.
- Trigger an error (e.g., duplicate email) → red toast for 6 s; press × to dismiss early.
- Screen reader (macOS VoiceOver: cmd+F5) announces the toast text.
- Toasts stack vertically when multiple fire in quick succession.

## Common traps

- **Using a `.ts` file for `$state`.** Svelte 5 runes require `.svelte.ts`. Without the extension, `$state` becomes a plain variable and nothing updates.
- **Putting the toaster inside a route-specific layout.** On navigation, the toaster unmounts and active toasts disappear. Always mount at the root.
- **Unkeyed `#each`.** Omit the `(toast.id)` key and Svelte re-renders every toast on change. Transitions break and users see flashes.
- **Using toasts for validation errors.** Inline field errors belong next to the field. Toasts are for action results, not form validation.
- **Using toasts for confirmation dialogs.** "Are you sure?" is not a toast. It's a modal. Toasts must not require a response to be actionable.

## Recap

Global store, 60-line component, one root-layout mount. Every action in the app can now acknowledge itself with one line of code. This is the smallest change with the largest per-interaction polish payoff in the entire course.
