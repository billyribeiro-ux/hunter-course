# 6.3.1 — Webhook Script

> One command boots the dev server and the Stripe listener together. Stop forgetting half your stack.

## Why this matters

You will, at some point, spend twenty minutes debugging a "broken" checkout flow before realising you didn't start `stripe listen`. Every SvelteKit + Stripe developer has done it. The failure mode is sneaky: your app runs, your Checkout redirect works, the payment completes — but the webhook never reaches your endpoint because nothing is forwarding events. You see the customer in the Stripe dashboard and empty tables in your database, and your first instinct is "my handler is broken."

It's not. You just forgot the listener.

The fix is mechanical: make "start dev" and "start stripe listen" literally the same command. Use `concurrently` to run both in one terminal with colour-coded output. Your muscle memory becomes `pnpm dev:all`, and the classic bug can't happen.

## The Principal Engineer lens

**Most "silly" bugs aren't about intelligence — they're about friction.** If the correct thing requires two terminals, a specific ordering, and remembering to stop both at the end of the day, people will forget. If the correct thing is one command, nobody forgets. Good infrastructure removes the chance to be stupid.

Corollary: **this is an ergonomic fix, not a technical necessity.** Two terminals absolutely works. Nothing in this lesson unlocks new capabilities. What it unlocks is a smoother loop, which compounds across hundreds of dev sessions.

## Step 1 — Install `concurrently` (pinned)

From `app/`:

```bash
pnpm add -D concurrently@9.2.0
```

Confirm in `app/package.json`:

```json
{
	"devDependencies": {
		"concurrently": "9.2.0"
	}
}
```

Dev dependency — it never ships to production. And pinned exact, same rule as every other dependency in the course.

`concurrently` is a tiny Node CLI that runs multiple commands in parallel, merges their output, and handles `Ctrl+C` cleanly (one keypress kills all the children). It's a mature tool — we've picked it over a shell one-liner because it handles the cross-platform edge cases for us (see Step 4).

## Step 2 — Add the `dev:all` script

Open `app/package.json` and add to `scripts`:

```json
{
	"scripts": {
		"dev": "vite dev",
		"dev:all": "concurrently -n web,stripe -c green,magenta 'pnpm dev' 'pnpm stripe:listen'",
		"stripe:listen": "stripe listen --forward-to http://localhost:5173/api/webhooks/stripe"
	}
}
```

Flag by flag:

- **`-n web,stripe`** — name the two streams. Every line of output gets prefixed `[web]` or `[stripe]` so you can tell which process said what.
- **`-c green,magenta`** — colour the prefixes. SvelteKit's own log output stays its usual colour; the prefix label is what gets recoloured. After two days you'll read the colours faster than the labels.
- **`'pnpm dev'`** — the SvelteKit Vite dev server.
- **`'pnpm stripe:listen'`** — the existing Stripe CLI forwarder from Lesson 5.3.

By default `concurrently` will exit when the *first* child exits, and send `SIGTERM` to the other. So if Vite crashes or you `Ctrl+C` either stream, both go down cleanly. No orphaned `stripe listen` processes.

## Step 3 — Use it

Kill any lingering `pnpm dev` or `stripe listen` processes first, then:

```bash
pnpm dev:all
```

You should see something like:

```
[web]    VITE v5.4.0 ready in 312 ms
[web]    ➜  Local: http://localhost:5173/
[stripe] > Ready! Your webhook signing secret is whsec_...
[stripe] > Forwarding events to http://localhost:5173/api/webhooks/stripe
```

Trigger an event from another terminal:

```bash
pnpm stripe:trigger:sub-created
```

And you'll see the event roll through both streams:

```
[stripe] 2026-04-19 10:12:03   --> customer.subscription.created [evt_1Nq...]
[stripe] 2026-04-19 10:12:03   <--  [200] POST http://localhost:5173/api/webhooks/stripe
[web]    [stripe webhook] customer.subscription.created evt_1Nq...
```

Both processes, one terminal, one `Ctrl+C` to stop.

## Step 4 — Platform notes

A few small things to know, most of which you've already accepted in earlier lessons:

- **macOS and Linux** — works out of the box. No quoting drama because `concurrently` parses its command strings itself, not via the shell.
- **Windows (native cmd or PowerShell)** — the pinned version of `concurrently` uses cross-spawn under the hood and handles quoting for both shells. Run from an integrated terminal in VS Code if you want a consistent experience.
- **WSL** — you'll want to run this inside WSL, not from Windows cmd, because the Stripe CLI binary has to be the Linux one for the Unix-socket forwarding to work reliably. We covered this in Lesson 5.3.1 — same rule applies here.

## Step 5 — Why not just a shell one-liner?

You could write:

```bash
pnpm dev & pnpm stripe:listen
```

It "works" on macOS and Linux. It does not work on Windows. It also leaks the background process if the foreground one crashes, and `Ctrl+C` only kills the foreground child. You'd be re-learning why `concurrently` exists every time a teammate on a different OS runs your script.

`concurrently` fixes all three: cross-platform, unified signal handling, named coloured output. Thirty extra bytes in `package.json`; no regrets.

## Step 6 — When *not* to use `dev:all`

Two genuine cases for keeping them separate:

- **Debugging signature issues.** If you're re-pasting `STRIPE_WEBHOOK_SECRET` repeatedly between `stripe listen` restarts, you'll want the listener on its own terminal so you can restart it without restarting Vite (and vice versa).
- **Triggering and watching at the same time.** You want three panes: Vite logs, `stripe listen`, and a free terminal to type `pnpm stripe:trigger:*`. `dev:all` gives you the first two merged; you still need the third.

In other words: `dev:all` is the default. Two terminals is a debugging tool.

## Verify

- `pnpm list concurrently` prints `concurrently 9.2.0`.
- `pnpm dev:all` starts both processes with `[web]` and `[stripe]` prefixes.
- Triggering an event shows the Stripe CLI log and the server log interleaved, both with correct prefixes.
- `Ctrl+C` once terminates both processes cleanly — no orphaned Node or Stripe processes (`ps aux | grep stripe` or Task Manager on Windows).

## Common traps

- **Running `pnpm dev:all` with `pnpm dev` already running in another terminal.** Vite will fail to bind port 5173 and `concurrently` will exit, killing `stripe listen` with it. Stop the stray process first.
- **Pasting an old `STRIPE_WEBHOOK_SECRET` into `.env`.** `stripe listen` rotates the secret on each start. `dev:all` makes this *more* visible, because you'll see the new `whsec_...` every time you boot. Copy it into `.env` whenever it changes.
- **Forgetting this is dev-only.** There is no `pnpm dev:all` in production. Production's webhook endpoint is a real HTTPS URL registered in the Stripe dashboard. We configure that in Module 12.
- **Adding `stripe listen` to a CI pipeline.** CI runs tests without real Stripe events; any webhook testing in CI should `POST` mocked payloads with freshly-signed HMACs, not tunnel through the CLI.

## Recap

`pnpm dev:all` replaces "did I remember both terminals?" with "yes, by construction." Eight-line `package.json` change, 100% of the convenience.
