# 3.2 — User Login

> The companion to registration: same remote-form pattern, a shorter schema, and one careful redirect.

## Why this matters

Login is the most security-sensitive form in your app. Get it wrong and you have a disaster. Get it right and every *other* protected route in your app gets a reliable `locals.user` for free. We'll build it with:

1. **Zod** — validates inputs before they hit the auth server.
2. **Supabase Auth** — verifies the password and writes a session cookie.
3. **A safe redirect** — honors `?next=...` only for same-origin relative paths.

## The Principal Engineer lens

We're reusing the remote `form()` pattern from 3.1. Why repeat it? Because the single biggest DX win in this course is **consistency**. Every form in our app looks the same:

- Zod schema at the top.
- `form(Schema, handler)` with `getRequestEvent()` for access to `locals`.
- `{ ok: false, message }` on failure, `throw redirect(303, ...)` on success.
- Page spreads `{...formName}` onto its `<form>` and renders `formName.result` for errors.

Internalize it once; reuse it forty times.

## Step 1 — Write the remote function

Create `src/routes/(auth)/login/auth.remote.ts`:

```ts
// src/routes/(auth)/login/auth.remote.ts
import { form, getRequestEvent } from '$app/server';
import { redirect } from '@sveltejs/kit';
import { z } from 'zod';

const LoginSchema = z.object({
	email: z.string().email('Enter a valid email address'),
	password: z.string().min(1, 'Password is required'),
	next: z.string().optional()
});

export const login = form(LoginSchema, async ({ email, password, next }) => {
	const { locals, url } = getRequestEvent();

	const { error } = await locals.supabase.auth.signInWithPassword({ email, password });
	if (error) {
		// Return a structured error; the page will render it.
		return { ok: false as const, message: error.message };
	}

	// Success — redirect to `next` if it's a safe relative path, else /contacts.
	const dest = next && next.startsWith('/') && !next.startsWith('//') ? next : '/contacts';
	throw redirect(303, dest);
});
```

Three things to stare at:

- **`form(LoginSchema, async ({...}) => ...)`** — the schema IS the input type. The handler body receives already-parsed, validated values.
- **`getRequestEvent()`** — remote functions don't take `event` as an argument; they call this helper. It returns the same thing a page load's `event` would.
- **`throw redirect(303, ...)`** — on success we leave; on failure we return a `{ ok: false, message }` shape the form page can render.

> **Why 303?** A 303 means "see other — GET this new URL." It's the correct code for a POST→GET transition, which prevents the "are you sure you want to resubmit?" dialog if the user hits back.

## Step 2 — Build the form

Now wire it up in `src/routes/(auth)/login/+page.svelte`:

```svelte
<script lang="ts">
	import { page } from '$app/state';
	import { login } from './auth.remote';

	const next = $derived(page.url.searchParams.get('next') ?? '');

	const result = $derived(login.result);
</script>

<h1 class="text-2xl font-semibold text-text-1">Welcome back</h1>
<p class="mt-2 text-sm text-text-2">Log in to your Contactly account.</p>

<form method="POST" {...login} class="mt-8 space-y-4">
	<input type="hidden" name="next" value={next} />

	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Email</span>
		<input
			type="email"
			name="email"
			autocomplete="email"
			required
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		/>
	</label>

	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Password</span>
		<input
			type="password"
			name="password"
			autocomplete="current-password"
			required
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		/>
	</label>

	{#if result && 'message' in result && !result.ok}
		<div role="alert" class="rounded-lg border border-red-500/30 bg-red-500/10 px-3 py-2 text-sm text-red-500">
			{result.message}
		</div>
	{/if}

	<button
		type="submit"
		class="w-full rounded-lg bg-brand-500 px-3 py-2.5 text-sm font-medium text-white hover:bg-brand-600 focus:outline-none focus:ring-2 focus:ring-brand-500 focus:ring-offset-2 focus:ring-offset-surface-1 disabled:opacity-60"
	>
		Log in
	</button>
</form>

<p class="mt-6 text-center text-sm text-text-2">
	Don't have an account?
	<a href="/register{next ? '?next=' + encodeURIComponent(next) : ''}" class="text-brand-500 hover:underline"
		>Sign up</a
	>
</p>
```

Points worth noticing:

- **`{...login}`** spreads the remote form's generated `method`, `action`, and progressive-enhancement handler onto the `<form>`. This is the secret sauce of remote forms.
- **`login.result`** is a reactive state the remote form maintains — it's set after each submission with whatever the server returned (or undefined if not yet submitted).
- **`page.url.searchParams`** comes from `$app/state` (May 2026 replacement for the older `$app/stores`).
- **`autocomplete="email"` / `"current-password"`** — tiny thing, huge UX win on mobile.

## Step 3 — Block signed-in users

Create `src/routes/(auth)/login/+page.server.ts`:

```ts
import type { PageServerLoad } from './$types';
import { requireGuest } from '$lib/server/auth';

export const load: PageServerLoad = async (event) => {
	requireGuest(event);
	return {};
};
```

Anyone who visits `/login` while logged in is redirected to `/contacts` — no flash of login form.

## Step 5 — Why we don't store "remember me"

You'll see "Remember me" checkboxes in many apps. Supabase sessions last 1 hour by default (`jwt_expiry = 3600` in `config.toml`), with auto-refresh via a refresh token that lasts weeks. In practice users stay logged in until they explicitly sign out or don't visit for a month. The checkbox is a relic of session-cookie days; skip it.

If you *must* implement it, read Supabase's docs on `persistSession` — but honestly, the simple version works.

## Step 6 — A note on progressive enhancement

Try this: open devtools, disable JavaScript, reload `/login`, submit. It still works. The browser posts the form, the server runs `login`, redirects. That's because remote forms degrade to plain HTML forms. This is not a party trick — it's resilience against broken JS bundles, slow networks, and aggressive ad blockers.

## Verify

- `/login` shows a styled form.
- Wrong password shows an inline error.
- Right password redirects to `/contacts` (which will 404 until Module 4).
- Visiting `/login` while signed in redirects to `/contacts`.

## Common traps

- **Forgetting `{...login}`** on the `<form>`. Without it, the form posts normally but without remote-function magic.
- **Using `svelte/store` for `page`.** The May 2026 way is `import { page } from '$app/state'`, and it's a rune — no `$page` prefix.
- **Returning a redirect inside the validator instead of the handler.** Validators are pure; they shouldn't redirect. Always redirect from the handler.
