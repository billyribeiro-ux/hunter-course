# 1.1 — SvelteKit Project Setup

> Create the project, pin everything, and make the very first commit.

## Why this matters

The shape of a repo on day one determines how pleasant it is to work in on day 180. We're going to set up:

- A pinned Node + pnpm version.
- A SvelteKit project with **TypeScript**, **Tailwind 4**, **Prettier**, **ESLint**, and **Playwright** — all wired up properly from the first minute.
- **Remote functions** enabled (the May 2026 SvelteKit pattern we'll use throughout).
- A clean initial commit so your git history tells a story.

## The Principal Engineer lens

You have two options when starting a project:

1. **Bare minimum now, add as we go.** Quick to start, painful to retrofit (especially ESLint and Playwright).
2. **Full setup upfront.** 20 minutes slower today, hours saved later.

We choose option 2. Every tool we add in this lesson either catches bugs or saves keystrokes. Doing it now also lets us ship a CI pipeline from Module 12 without last-minute panic.

## Step 1 — Create the SvelteKit project

From your `~/code` directory:

```bash
mkdir contactly && cd contactly
pnpm create svelte@latest app
```

Answer the prompts:

| Prompt | Answer |
|---|---|
| Which Svelte app template? | **Skeleton project** |
| Add type checking? | **TypeScript** |
| Select additional options | **ESLint**, **Prettier**, **Playwright**, **Vitest** (optional) |

Then:

```bash
cd app
pnpm install
```

You now have a working SvelteKit app. Run it:

```bash
pnpm dev
```

Visit http://localhost:5173 — you should see the skeleton homepage. Stop it with `Ctrl+C`.

## Step 2 — Pin Node & pnpm versions

Create `.nvmrc`:

```
24.16.0
```

And in `package.json`, add:

```json
{
  "engines": {
    "node": ">=24.16 <25",
    "pnpm": ">=11.5"
  },
  "packageManager": "pnpm@11.5.0"
}
```

Now *everyone* — teammates, CI, future you — uses the same runtime. `fnm` and `volta` both auto-switch when they see `.nvmrc`.

## Step 4 — Enable Tailwind 4

Tailwind 4 is CSS-first: no `tailwind.config.js` needed. Replace `src/app.css` with:

```css
@import 'tailwindcss';

@theme {
  --color-brand-500: #2563eb;
  /* we'll fill in the full palette in Module 13 */
}
```

Then wire the Tailwind Vite plugin. Replace `vite.config.ts`:

```ts
import { sveltekit } from '@sveltejs/kit/vite';
import tailwindcss from '@tailwindcss/vite';
import { defineConfig } from 'vite';

export default defineConfig({
  plugins: [tailwindcss(), sveltekit()],
  server: { port: 5173, strictPort: true }
});
```

Import the CSS in `src/routes/+layout.svelte`:

```svelte
<script lang="ts">
  import '../app.css';
  let { children } = $props();
</script>

{@render children()}
```

Spin up the dev server again: `pnpm dev`. Open the page — you now have Tailwind available. Try adding `class="text-4xl font-bold"` to a heading on the home page to prove it.

## Step 5 — Enable SvelteKit remote functions

Remote functions are **the** May 2026 SvelteKit pattern. They replace most `+page.server.ts` load/action boilerplate. To enable them, update `svelte.config.js`:

```js
import adapter from '@sveltejs/adapter-vercel';
import { vitePreprocess } from '@sveltejs/vite-plugin-svelte';

/** @type {import('@sveltejs/kit').Config} */
const config = {
  preprocess: vitePreprocess(),
  kit: {
    adapter: adapter({ runtime: 'nodejs24.x' }),
    alias: { $lib: 'src/lib' },
    experimental: { remoteFunctions: true }
  },
  compilerOptions: {
    experimental: { async: true }
  }
};

export default config;
```

The two flags:

- `kit.experimental.remoteFunctions: true` — lets us create `.remote.ts` files that export `query()`, `form()`, `command()`.
- `compilerOptions.experimental.async: true` — lets us use `{#await getX()}` directly in components.

> **Principal Engineer note:** these are marked "experimental" but are the stable shipping API in 2.55. The flag is a migration lever for teams who aren't ready.

## Step 6 — TypeScript config

Edit `tsconfig.json`:

```json
{
  "extends": "./.svelte-kit/tsconfig.json",
  "compilerOptions": {
    "allowJs": true,
    "checkJs": true,
    "esModuleInterop": true,
    "forceConsistentCasingInFileNames": true,
    "resolveJsonModule": true,
    "skipLibCheck": true,
    "sourceMap": true,
    "strict": true,
    "moduleResolution": "bundler",
    "module": "esnext",
    "target": "esnext",
    "noUncheckedIndexedAccess": true,
    "verbatimModuleSyntax": true
  }
}
```

Two Principal-Engineer-grade flags:

- `noUncheckedIndexedAccess` — array access returns `T | undefined`. Saves you from "cannot read property of undefined" in production.
- `verbatimModuleSyntax` — forces `import type` for type-only imports. Plays nicely with the SvelteKit + Vite build.

## Step 7 — Prettier & ESLint

Create `.prettierrc`:

```json
{
  "useTabs": true,
  "singleQuote": true,
  "trailingComma": "none",
  "printWidth": 100,
  "plugins": ["prettier-plugin-svelte", "prettier-plugin-tailwindcss"],
  "overrides": [{ "files": "*.svelte", "options": { "parser": "svelte" } }]
}
```

And `eslint.config.js` (flat config — the only supported mode):

```js
import js from '@eslint/js';
import svelte from 'eslint-plugin-svelte';
import prettier from 'eslint-config-prettier';
import globals from 'globals';
import ts from 'typescript-eslint';

export default ts.config(
  js.configs.recommended,
  ...ts.configs.recommended,
  ...svelte.configs['flat/recommended'],
  prettier,
  ...svelte.configs['flat/prettier'],
  {
    languageOptions: { globals: { ...globals.browser, ...globals.node } }
  },
  {
    files: ['**/*.svelte'],
    languageOptions: { parserOptions: { parser: ts.parser } }
  },
  {
    ignores: ['build/', '.svelte-kit/', 'dist/', 'src/lib/types/database.types.ts']
  }
);
```

Add scripts to `package.json`:

```json
{
  "scripts": {
    "dev": "vite dev",
    "build": "vite build",
    "preview": "vite preview",
    "check": "svelte-kit sync && svelte-check --tsconfig ./tsconfig.json",
    "typecheck": "tsc --noEmit",
    "lint": "prettier --check . && eslint .",
    "format": "prettier --write .",
    "test": "playwright test"
  }
}
```

Run them:

```bash
pnpm check    # should pass
pnpm lint     # might complain about the skeleton; pnpm format fixes it
```

## Step 8 — The first commit

If `pnpm create svelte` already initialized a repo, great. Otherwise:

```bash
cd ..          # back to ~/code/contactly
git init
git add .
git commit -m "chore: scaffold SvelteKit 2.55 + TS + Tailwind 4 + remote functions

Pinned Node 24.16, pnpm 11.5. Tooling: ESLint flat config,
Prettier, Playwright, Vitest. Remote functions enabled via
svelte.config.js experimental flags."
```

That's the shape of a commit message a Principal Engineer writes: **what** in the subject, **why** in the body, no fluff.

## Verify

```bash
pnpm dev
```

- Open http://localhost:5173 — you should see the skeleton page styled with Tailwind.
- Stop it. Run `pnpm check` — clean.
- Run `pnpm lint` — clean (or run `pnpm format` first).

## Common traps

- **Tailwind classes aren't applied.** You forgot to import `app.css` in `+layout.svelte`.
- **`$lib` import fails.** You skipped the `alias: { $lib: 'src/lib' }` line.
- **`pnpm install` complains about the lockfile.** Delete `pnpm-lock.yaml` and re-run once; subsequent installs must match the lockfile.
