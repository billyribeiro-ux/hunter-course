# 5.5 — Creating Products & Prices

> Once by hand, so you see the fields. Then never again — Module 8 automates it.

## Why this matters

Even though our production flow uses a seed script (`scripts/seed-stripe.ts`), creating a Product and a Price once in the dashboard is the fastest way to see every field that exists. You'll understand what the script is doing because you've done it manually first.

## The Principal Engineer lens

**Manual once, scripted forever.** Any config that drifts between environments is a future bug. After this lesson, every change to Contactly's pricing — a new tier, a new interval, a new currency — happens through code and PR review. The dashboard becomes read-only.

## Step 1 — Create the Plus product

In the Stripe dashboard (test mode):

1. Go to **Products** → **+ Add product**.
2. **Name**: `Plus`.
3. **Description**: `More contacts, priority email support.` (shown on invoices and the hosted checkout.)
4. Skip image (optional).
5. **Pricing** section: we'll create the first price right here.

## Step 2 — Create the monthly Plus price

In the same form:

- **Pricing model**: Standard pricing.
- **Price**: `10.00 USD`.
- **Billing period**: Monthly.
- **Tax behavior**: Exclusive (default).
- Click **Advanced options**:
  - **Lookup key**: `plus_monthly`. (Critical — this is the stable handle we'll resolve in code.)
  - **Price description**: `Plus monthly (v1)` — for your future-self sanity.

Click **Save product**.

You'll land on the Plus product page. You should see one Price listed with the lookup key `plus_monthly`.

## Step 3 — Add the yearly Plus price

From the Plus product page:

1. **+ Add another price**.
2. **Price**: `96.00 USD` (20% off vs. paying monthly).
3. **Billing period**: Yearly.
4. **Advanced options**:
   - **Lookup key**: `plus_yearly`.
   - **Description**: `Plus yearly (v1)`.
5. Save.

Plus now has two prices. Same product, same descriptions, same tax behavior.

## Step 4 — Create the Pro product + its prices

Repeat for Pro:

- Product: **Pro** — "Unlimited contacts, premium support."
- Price 1: $20/month, lookup key `pro_monthly`.
- Price 2: $192/year, lookup key `pro_yearly`.

When you're done, **Products** shows:

- Plus — 2 prices
- Pro — 2 prices

## Step 5 — Verify lookup keys

Click **Developers → API → List Prices** in the dashboard and filter by lookup key:

```bash
# Example CLI lookup
stripe prices list --lookup-keys plus_monthly,plus_yearly,pro_monthly,pro_yearly
```

You should see 4 Price objects. Copy one of their IDs — those start with `price_...`. We won't hardcode them, but it's useful to see the shape.

## Step 6 — Why lookup keys matter

Here's the payoff. In Module 6's code we'll ask Stripe for a Price by its lookup key, not by ID:

```ts
const prices = await stripe.prices.list({
	lookup_keys: ['plus_monthly'],
	expand: ['data.product']
});
const price = prices.data[0]; // stable reference
```

Advantages:

- **The same code works across test and live environments.** Test mode has its own `plus_monthly`; live has its own; you don't need two sets of hardcoded IDs.
- **Recreating a price (e.g., price change) is seamless.** Archive the old, create a new with the same lookup key, and your app just... picks up the new one.
- **No drift between your seed script and the dashboard.** Both reference the same stable name.

## Step 7 — Describe this config in code now

Open `src/lib/config/pricing.ts` (we scaffolded this earlier). It should look like:

```ts
// src/lib/config/pricing.ts
export type TierId = 'free' | 'plus' | 'pro';
export type Interval = 'monthly' | 'yearly';

export interface TierConfig {
	id: TierId;
	name: string;
	description: string;
	contactLimit: number | null; // null = unlimited
	prices: Partial<Record<Interval, string>>; // interval -> lookup_key
}

export const TIERS: TierConfig[] = [
	{
		id: 'free',
		name: 'Free',
		description: 'Get started with basic contact management.',
		contactLimit: 5,
		prices: {}
	},
	{
		id: 'plus',
		name: 'Plus',
		description: 'More contacts, priority email support.',
		contactLimit: 25,
		prices: { monthly: 'plus_monthly', yearly: 'plus_yearly' }
	},
	{
		id: 'pro',
		name: 'Pro',
		description: 'Unlimited contacts, premium support.',
		contactLimit: null,
		prices: { monthly: 'pro_monthly', yearly: 'pro_yearly' }
	}
];
```

This is the app's pricing *meta*-config. Stripe owns the amounts; this file owns the tier shape + lookup-key map. We'll use both halves together.

## Step 8 — What we're about to automate

By the end of Module 8 we'll have a script (`scripts/seed-stripe.ts`) that reads this config, checks which lookup keys already exist in Stripe, creates the missing Products and Prices, and is idempotent (safe to re-run). You'll never click through the dashboard again.

For now, the manual setup serves a clear purpose: it gives us a working test environment so the next few lessons can reference real Products and Prices.

## Verify

- Two products visible in the dashboard: Plus and Pro.
- Four prices total, with lookup keys `plus_monthly`, `plus_yearly`, `pro_monthly`, `pro_yearly`.
- Amounts are $10 / $96 / $20 / $192 in USD.
- `src/lib/config/pricing.ts` reflects the same structure.

## Common traps

- **Leaving the lookup key blank.** Easy to forget — it's under "Advanced options." Without it, you have to hardcode price IDs. Don't.
- **Creating the Products in live mode instead of test mode.** Check the dashboard toggle before every create.
- **Setting the year price as `$120` "just to get a round number."** You can, but our code assumes a 20% yearly discount for Module 8's display. Keep amounts honest with what you'll market.
