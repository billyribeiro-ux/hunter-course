# 8.4 — Pricing Page

> Public, server-rendered, zero-JavaScript-until-you-interact. The one page every SaaS needs to nail.

## Why this matters

The pricing page is simultaneously the most marketing-critical surface of your app and the most data-dependent. It has to render fast (SEO + conversion), show correct prices (no drift between UI and Stripe), adapt to the logged-in user's current plan (right CTA per row), and gracefully handle Stripe outages (don't let a slow Stripe call block the whole page).

Most pricing pages get this wrong in one of three ways: they hardcode prices, they call Stripe from the browser, or they're pure client-side React that SEO crawlers can't read. Ours does none of those. A `+page.server.ts` loader pre-fetches everything, the page renders with real HTML on first response, and the interval toggle is the only hydration required.

## The Principal Engineer lens

**The pricing page is your single biggest integration test.** If it renders with correct amounts, correct CTAs for each viewer state, and correct links to checkout, every other part of the billing stack is probably working. When bug reports come in, this is the page you reload first.

Corollary: **render from a single cohesive data source.** We already built `listPricingPageTiers()` in 8.3 — one call, all data. The template has no `if (tier.id === 'plus') fetchExtra()` branches. Data in, HTML out.

## Step 1 — Route structure

Pricing is public, so it lives *outside* the `(app)` guarded group. Create:

```
src/routes/
	(marketing)/
		+layout.svelte            ← marketing chrome (nav, footer)
		pricing/
			+page.server.ts
			+page.svelte
```

`(marketing)` is a new route group — logged-in users can still see it (the page adapts), but there's no `requireUser` guard. The marketing layout renders simpler nav (no user menu for logged-out visitors; we'll conditionally show it for logged-in).

## Step 3 — The page server loader

`src/routes/(marketing)/pricing/+page.server.ts`:

```ts
// src/routes/(marketing)/pricing/+page.server.ts
import type { PageServerLoad } from './$types';
import { listPricingPageTiers } from '$lib/server/billing/pricing-page';
import { getActiveSubscription, tierIdFromLookupKey } from '$lib/server/billing/subscriptions';

export const load: PageServerLoad = async ({ locals }) => {
	const pageTiers = await listPricingPageTiers();

	// If logged in, figure out the user's current tier so CTAs can adapt.
	let currentTierId: 'free' | 'plus' | 'pro' = 'free';
	if (locals.user) {
		const sub = await getActiveSubscription(locals.supabaseAdmin, locals.user.id);
		currentTierId = tierIdFromLookupKey(sub?.price_lookup_key ?? null);
	}

	return { pageTiers, currentTierId };
};
```

Three decisions worth a beat:

- **We call `listPricingPageTiers()` server-side.** It hits Stripe once per 5 minutes (the cache from 7.2), returns a typed DTO, and the rendered HTML contains real amounts. SEO is happy; users see prices instantly.
- **Current tier is resolved on the server when logged in.** No "loading your plan..." flash on initial render.
- **We allow (not require) a user.** Logged-out visitors get `currentTierId = 'free'` and see "Sign up" CTAs.

## Step 4 — The page template

`src/routes/(marketing)/pricing/+page.svelte`:

```svelte

					: 'text-muted-foreground'}"
				onclick={() => (interval = 'yearly')}
			>
				Yearly
				<span class="text-xs text-emerald-600 dark:text-emerald-400">
					{PRICING_YEARLY_DISCOUNT_LABEL}
				</span>
			</button>
		</div>

	<div class="mt-12 grid gap-6 md:grid-cols-3 max-w-5xl mx-auto">
		{#each data.pageTiers as entry (entry.tier.id)}
			<TierCard
				tier={entry.tier}
				presentation={entry.presentation}
				{interval}
				currentTierId={data.currentTierId}
				{formatPerMonth}
			/>

```

The interval state lives in the top-level component. Child cards receive it via props and re-render when it flips. No stores, no context — Svelte 5 runes plus props is enough.

## Step 5 — The tier card component

`src/routes/(marketing)/pricing/TierCard.svelte`:

```svelte
<script lang="ts">
	import type { Tier, TierPrice } from '$lib/server/billing/types';
	import type { PricingTierPresentation } from '$lib/config/pricing-page';
	import type { TierId } from '$lib/config/pricing';

	type Props = {
		tier: Tier;
		presentation: PricingTierPresentation;
		interval: 'monthly' | 'yearly';
		currentTierId: TierId;
		formatPerMonth: (cents: number, interval: 'monthly' | 'yearly') => string;
	};
	let { tier, presentation, interval, currentTierId, formatPerMonth }: Props = $props();

	let price = $derived<TierPrice | undefined>(
		tier.prices.find((p) => p.interval === interval)
	);

	let cta = $derived(
		currentTierId === tier.id
			? presentation.ctaCurrent
			: currentTierId === 'free'
				? presentation.ctaFree
				: presentation.ctaOther
	);

	let isCurrent = $derived(currentTierId === tier.id);
	let href = $derived(
		tier.id === 'free'
			? '/register'
			: isCurrent
				? '/account'
				: `/app/upgrade?lookup=${price?.lookupKey ?? ''}`
	);
</script>

<div
	class="rounded-2xl border p-6 flex flex-col {presentation.highlighted
		? 'border-primary shadow-lg'
		: 'border-border'}"
>
	{#if presentation.highlighted}
		<span class="self-start rounded-full bg-primary/10 px-2 py-0.5 text-xs font-medium text-primary">
			Most popular
		</span>
	{/if}

	<h2 class="mt-2 text-xl font-semibold">{tier.name}</h2>
	<p class="mt-1 text-sm text-muted-foreground">{presentation.tagline}</p>

	<div class="mt-6">
		{#if tier.id === 'free'}
			<div class="text-3xl font-bold">$0</div>
			<div class="text-sm text-muted-foreground">forever</div>
		{:else if price}
			<div class="text-3xl font-bold">{formatPerMonth(price.unitAmount, interval)}</div>
			<div class="text-sm text-muted-foreground">
				{interval === 'yearly' ? 'billed annually' : 'billed monthly'}
			</div>
		{:else}
			<div class="text-sm text-muted-foreground italic">Temporarily unavailable</div>
		{/if}
	</div>

	<ul class="mt-6 space-y-2 text-sm flex-1">
		{#each presentation.bullets as bullet (bullet)}
			<li class="flex items-start gap-2">
				<span aria-hidden="true" class="mt-0.5 text-primary">✓</span>
				<span>{bullet}</span>
			</li>
		{/each}
	</ul>

	<a
		{href}
		aria-disabled={isCurrent && tier.id === 'free'}
		class="mt-6 inline-flex justify-center rounded-md px-4 py-2 text-sm font-medium transition {presentation.highlighted
			? 'bg-primary text-primary-foreground hover:bg-primary/90'
			: 'border border-border hover:bg-muted'} {isCurrent && tier.id === 'free'
			? 'pointer-events-none opacity-60'
			: ''}"
	>
		{cta}
	</a>
</div>
```

The component reads like a truth table: `tier × interval × currentTierId → rendered card`. Every decision is a `$derived` expression, so the card reacts cleanly when the interval toggle flips.

## Step 6 — Handling missing prices gracefully

The `{:else}` branch in the price block (`<div class="text-sm text-muted-foreground italic">Temporarily unavailable</div>`) is what shows if `tier.prices` doesn't contain a match for the current interval. Under normal conditions this never happens — the seed has all four prices. But if someone archives one manually, the page degrades to "Temporarily unavailable" with no CTA, rather than throwing.

This is the resilience rule: **broken data should degrade the page, not break the app.**

## Step 7 — Verifying the upgrade link target

The `href` for a paid tier CTA points at `/app/upgrade?lookup=plus_monthly`. That route doesn't exist yet — Module 9.1 creates it. For now, clicking the CTA on an anonymous user lands at `/register` (no Stripe interaction); on a logged-in user it lands at `/app/upgrade`, which 404s *intentionally* until Module 9. Good — you can't upgrade to nothing.

## Step 8 — Accessibility notes

A couple of small but important touches:

- **The interval toggle uses `role="tablist"` + `role="tab"` + `aria-selected`.** Screen readers announce "Monthly tab, selected" correctly.
- **CTAs are `<a>` tags, not `<button>`s, because they navigate.** `aria-disabled` on the "Current plan" link communicates non-interactivity without removing it from the DOM.
- **Contrast.** The highlighted card's primary colour has to meet AA contrast against `primary-foreground`. Module 13.3 revisits this with design tokens; right now, verify in DevTools.

## Step 9 — Cacheability

Add HTTP caching hints in the loader, so the first anonymous request is a bit faster on second-hit visits:

```ts
// src/routes/(marketing)/pricing/+page.server.ts (add to the load return)
export const load: PageServerLoad = async ({ locals, setHeaders }) => {
	// ...existing logic...

	// Only cache for anonymous visitors — logged-in pages have personalized CTAs.
	if (!locals.user) {
		setHeaders({
			'Cache-Control': 'public, max-age=60, s-maxage=300'
		});
	}

	return { pageTiers, currentTierId };
};
```

Anonymous visitors get a 60-second browser cache and a 5-minute CDN cache. Logged-in visitors get fresh HTML (their CTAs differ). On Vercel, the `s-maxage=300` is honoured by the edge network automatically.

- Plus is the highlighted card with the "Most popular" badge.
- Toggling Monthly/Yearly changes the amounts *and* the billing cadence line below.

## Common traps

- **Fetching tiers client-side via a `fetch()` in `onMount`.** Breaks SEO and adds a flash. Always use `+page.server.ts`.
- **Hardcoding the interval toggle's saved-percent label.** Derive from the actual Stripe amounts (or at least assert with the util from 8.3) so marketing and reality don't drift.
- **Putting the upgrade flow on the tier card itself** (i.e., creating the Checkout session inline). Module 9 handles that as a dedicated route — keeps the pricing page a pure presentation layer.
- **Skipping the `(marketing)` route group.** Putting pricing under `(app)` would require a login to see it. Pricing is public.
