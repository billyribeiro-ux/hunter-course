# 4.5 — Reading Contacts

> Our first `query()` remote function, rendered with the async-await syntax in Svelte 5.

## Why this matters

This is where remote functions really sing. `query()` is the cousin of `form()` for reads:

- It returns a typed `Promise<T>` that you can `await` directly in the template.
- It's cached per-render with keyed invalidation (`getContacts().refresh()` after writes).
- It's colocated with the write handlers — no `/api/contacts` route needed.

We'll build `getContacts()`, render the list with `{#await}` + loading/error states, and wire our create flow to auto-refresh on save.

## The Principal Engineer lens

**One source of truth for reads.** Every component that needs the contacts list calls `getContacts()`. Same query, same cache, same refresh. No duplicated fetch logic, no "which one is canonical?" debate.

**Render loading, error, and data states explicitly.** Skeleton on loading, an actionable message on error, the list on success. Skip any state and the UI will flicker or feel broken.

## Step 1 — Add `getContacts` to the remote file

Edit `src/routes/(app)/contacts/contacts.remote.ts` — keep the existing `createContact` and add:

```ts
// add to src/routes/(app)/contacts/contacts.remote.ts
import { query } from '$app/server';
// (form, getRequestEvent, z, requireUser already imported)

export const getContacts = query(async () => {
	const event = getRequestEvent();
	const user = requireUser(event);

	const { data, error } = await event.locals.supabase
		.from('contacts')
		.select('id, full_name, email, phone, notes, created_at, updated_at')
		.eq('user_id', user.id)
		.order('created_at', { ascending: false });

	if (error) throw new Error(error.message);
	return data;
});
```

Points to notice:

- **No Zod schema for a `query()` with no arguments.** `query()` takes an async function; Zod comes in when the query accepts input.
- **Explicit column list** (`select('id, full_name, ...')`) — shields the wire format from accidental schema changes. Adding a new column to the table doesn't automatically ship it to the browser.
- **`.eq('user_id', user.id)`** belt-and-suspenders ownership filter (RLS already enforces it).
- **`.order('created_at', { ascending: false })`** — newest first. Uses our composite index from 4.1.
- **`throw new Error(...)` on failure** — query errors propagate to the `{#await}` catch branch in the template.

## Step 2 — Render the list with `{#await}`

Edit `src/routes/(app)/contacts/+page.svelte`:

```svelte
<script lang="ts">
	import Dialog from '$lib/components/Dialog.svelte';
	import ContactForm from './ContactForm.svelte';
	import ContactRow from './ContactRow.svelte';
	import { getContacts } from './contacts.remote';

	let showCreate = $state(false);
	const contactsPromise = $derived(getContacts());
</script>

<div class="flex items-center justify-between">
	<h1 class="text-2xl font-semibold text-text-1">Contacts</h1>
	<button
		class="rounded-lg bg-brand-500 px-4 py-2 text-sm font-medium text-white hover:bg-brand-600"
		onclick={() => (showCreate = true)}
	>
		+ New contact
	</button>
</div>

{#await contactsPromise}
	<div class="mt-8 space-y-2">
		{#each { length: 3 } as _, i (i)}
			<div class="h-14 animate-pulse rounded-lg bg-surface-1"></div>
		{/each}
	</div>
{:then contacts}
	{#if contacts.length === 0}
		<div class="mt-10 rounded-xl border border-dashed border-border-1 bg-surface-1 p-10 text-center">
			<p class="text-base text-text-1">No contacts yet</p>
			<p class="mt-1 text-sm text-text-2">Click "New contact" to add your first one.</p>
		</div>
	{:else}
		<ul class="mt-6 divide-y divide-border-1 overflow-hidden rounded-xl border border-border-1 bg-surface-1">
			{#each contacts as c (c.id)}
				<ContactRow contact={c} />
			{/each}
		</ul>
	{/if}
{:catch err}
	<div role="alert" class="mt-8 rounded-lg border border-red-500/30 bg-red-500/10 px-4 py-3 text-sm text-red-500">
		Couldn't load contacts: {err.message}
	</div>
{/await}

<Dialog open={showCreate} title="New contact" onClose={() => (showCreate = false)}>
	<ContactForm
		onDone={() => {
			showCreate = false;
			void getContacts().refresh();
		}}
	/>
</Dialog>
```

What's new:

- **`{#await promise}...{:then data}...{:catch err}...{/await}`** — Svelte's native async rendering. The `compilerOptions.experimental.async` flag we set in Lesson 1.1 makes this work inside component bodies.
- **Skeleton rows** — three pulsing placeholder rectangles while the promise is pending. Much nicer than "Loading..." text.
- **Empty state** — first-time users get a friendly card, not an empty page.
- **`void getContacts().refresh()`** — the key detail. After a successful create, we re-run the query. `.refresh()` is built into every `query()`-returned function. The `void` discards the returned promise since we don't need to await it (fire and forget).

## Step 3 — The row component

Create `src/routes/(app)/contacts/ContactRow.svelte`:

```svelte
<script lang="ts">
	import type { Contact } from '$lib/types/db';

	interface Props {
		contact: Pick<Contact, 'id' | 'full_name' | 'email' | 'phone'>;
	}
	let { contact }: Props = $props();

	function initials(name: string) {
		return name
			.split(/\s+/)
			.slice(0, 2)
			.map((s) => s[0]?.toUpperCase() ?? '')
			.join('');
	}
</script>

<li class="flex items-center gap-4 px-4 py-3 hover:bg-surface-0">
	<span class="grid h-9 w-9 shrink-0 place-items-center rounded-full bg-brand-500/10 text-sm font-semibold text-brand-500">
		{initials(contact.full_name)}
	</span>
	<div class="min-w-0 flex-1">
		<p class="truncate text-sm font-medium text-text-1">{contact.full_name}</p>
		<p class="truncate text-xs text-text-2">{contact.email ?? contact.phone ?? '—'}</p>
	</div>
</li>
```

Design notes:

- **`Pick<Contact, ...>`** — we only use four fields in this component, so we narrow the type. Makes it composable with views that select fewer columns.
- **Initials avatar** — colored, branded, identifiable at a glance.
- **Truncate** on both lines — never let long notes break the layout.

## Step 5 — Why `query()` is not just a wrapped `fetch`

Two practical wins over rolling your own fetch:

1. **Typed end-to-end.** `getContacts()` returns `Promise<Contact[]>` because TypeScript infers from the return type. No manual DTOs.
2. **Reactive-aware.** The `$derived(getContacts())` creates a stable, cached promise per component instance. `.refresh()` invalidates that cache and re-runs, but only where the query is used.

You get a micro-SWR / React Query experience without the library.

## Step 6 — The "refresh after mutate" pattern

Across the app, writes will follow this pattern:

```ts
// Inside a remote form or command handler
await doTheWrite();
return { ok: true, ... };
```

```svelte
<!-- In the component using the result -->
{#if result?.ok}
  { void getX().refresh(); }   // (conceptual)
{/if}
```

Or, more practically, inside the `onDone` callback of the form component — where we *know* success happened — we call `getX().refresh()`. That's exactly what we did above.

> If you're used to a traditional `fetch` setup, this is the replacement for "call the GET again after the POST succeeds, and update local state." `query + refresh` handles it.

## Common traps

- **Calling `getContacts()` directly in the template without `$derived`.** Each render would be a new promise, refetching infinitely. Always assign to `const x = $derived(getContacts())`.
- **Forgetting `.refresh()` after a write.** Symptom: you create a contact and the list doesn't update until you reload. Call `.refresh()` in the success callback.
- **Selecting `*`.** Ships columns to the browser that the UI doesn't need. Explicit column lists are good discipline.
