# 4.3 — Creating Contacts

> The first row your app writes: a validated, authenticated, RLS-enforced insert. One remote function does it all.

## Why this matters

"Add a contact" is the simplest mutation in the app, which makes it the perfect place to lock down the pattern we'll reuse for every other write:

- A Zod schema for the shape.
- A remote `form()` function in a `.remote.ts` file.
- An inline `requireUser()` gate.
- A `.refresh()` call to invalidate the list.

Ship this cleanly and the rest of CRUD is muscle memory.

## The Principal Engineer lens

**Insert = single database round-trip.** No client-side ID generation (let Postgres pick the UUID). No "soft" validation in the UI followed by a "real" check on the server — just one Zod schema that runs server-side. The UI can mirror the constraints for UX, but the server is canonical.

**Normalize inputs at the boundary.** Trim strings, lowercase emails, strip phone-format noise. Downstream code should trust that the data is clean.

## Step 1 — Create the contacts route

```bash
mkdir -p src/routes/\(app\)/contacts
```

The route lives under `(app)` so the `requireUser` guard from 3.3 applies automatically.

## Step 2 — Write the remote function for create

Create `src/routes/(app)/contacts/contacts.remote.ts` (we'll add read/update/delete in the next lessons):

```ts
// src/routes/(app)/contacts/contacts.remote.ts
import { form, getRequestEvent } from '$app/server';
import { z } from 'zod';
import { requireUser } from '$lib/server/auth';

const ContactSchema = z.object({
	full_name: z.string().trim().min(1, 'Name is required').max(100),
	email: z.string().trim().toLowerCase().email('Enter a valid email').or(z.literal('')).optional(),
	phone: z.string().trim().max(40).optional(),
	notes: z.string().trim().max(1000).optional()
});

export const createContact = form(ContactSchema, async ({ full_name, email, phone, notes }) => {
	const event = getRequestEvent();
	const user = requireUser(event);

	const { data, error } = await event.locals.supabase
		.from('contacts')
		.insert({
			user_id: user.id,
			full_name,
			email: email || null,
			phone: phone || null,
			notes: notes || null
		})
		.select()
		.single();

	if (error) return { ok: false as const, message: error.message };
	return { ok: true as const, contact: data };
});
```

Things worth explaining:

- **`.trim().toLowerCase().email()`** — chainable Zod transforms. The email is sanitized *before* the format check; if a user types `"  Foo@Bar.com "`, it becomes `"foo@bar.com"` and then we validate.
- **`.or(z.literal('')).optional()`** — email can be missing, or an empty string (from an empty form field), or a valid email. All three are fine.
- **`email: email || null`** — Postgres prefers `null` over empty strings for "no value." Coerce here.
- **`.insert(...).select().single()`** — tell PostgREST "insert, and return the new row as a single object." Saves a round-trip.

## Step 3 — Build the "new contact" form component

We'll use a simple dialog/modal pattern. Create `src/lib/components/Dialog.svelte` — a reusable modal container:

```svelte
<!-- src/lib/components/Dialog.svelte -->
<script lang="ts">
	import type { Snippet } from 'svelte';

	interface Props {
		open: boolean;
		title: string;
		onClose: () => void;
		children: Snippet;
	}
	let { open, title, onClose, children }: Props = $props();

	function handleBackdrop(e: MouseEvent) {
		if (e.target === e.currentTarget) onClose();
	}

	$effect(() => {
		if (!open) return;
		function onKey(e: KeyboardEvent) {
			if (e.key === 'Escape') onClose();
		}
		window.addEventListener('keydown', onKey);
		return () => window.removeEventListener('keydown', onKey);
	});
</script>

{#if open}
	<div
		class="fixed inset-0 z-40 flex items-center justify-center bg-black/60 px-4"
		role="dialog"
		aria-modal="true"
		onclick={handleBackdrop}
	>
		<div
			class="w-full max-w-md rounded-2xl border border-border-1 bg-surface-1 p-6 shadow-2xl"
			role="document"
		>
			<div class="mb-4 flex items-start justify-between gap-4">
				<h2 class="text-lg font-semibold text-text-1">{title}</h2>
				<button
					type="button"
					class="text-text-2 hover:text-text-1"
					aria-label="Close"
					onclick={onClose}>✕</button
				>
			</div>
			{@render children()}
		</div>
	</div>
{/if}
```

Key bits:

- **`Snippet` import** — Svelte 5 replaces old slot API with snippets. `children: Snippet` is a typed renderable.
- **`role="dialog"` + `aria-modal="true"`** — accessibility. Screen readers trap inside.
- **Escape to close + click-backdrop to close** — both are table stakes for modals; users expect them.

## Step 4 — Create a contact form component

Create `src/routes/(app)/contacts/ContactForm.svelte`:

```svelte
<script lang="ts">
	import { createContact } from './contacts.remote';
	import type { Contact } from '$lib/types/db';

	interface Props {
		onDone: (c: Contact | null) => void;
	}
	let { onDone }: Props = $props();

	const result = $derived(createContact.result);

	$effect(() => {
		if (result?.ok) {
			onDone(result.contact);
		}
	});
</script>

<form method="POST" {...createContact} class="space-y-3">
	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Full name</span>
		<!-- svelte-ignore a11y_autofocus -->
		<input
			name="full_name"
			required
			autofocus
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		/>
	</label>
	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Email</span>
		<input
			type="email"
			name="email"
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		/>
	</label>
	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Phone</span>
		<input
			name="phone"
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		/>
	</label>
	<label class="block text-sm">
		<span class="mb-1 block text-text-2">Notes</span>
		<textarea
			name="notes"
			rows="3"
			class="w-full rounded-lg border border-border-1 bg-surface-0 px-3 py-2 text-text-1 focus:outline-none focus:ring-2 focus:ring-brand-500"
		></textarea>
	</label>

	{#if result && !result.ok}
		<div role="alert" class="rounded-lg border border-red-500/30 bg-red-500/10 px-3 py-2 text-sm text-red-500">
			{result.message}
		</div>
	{/if}

	<div class="flex items-center justify-end gap-2 pt-2">
		<button
			type="button"
			class="rounded-lg border border-border-1 px-3 py-2 text-sm text-text-1 hover:bg-surface-0"
			onclick={() => onDone(null)}
		>
			Cancel
		</button>
		<button
			type="submit"
			class="rounded-lg bg-brand-500 px-4 py-2 text-sm font-medium text-white hover:bg-brand-600"
		>
			Save contact
		</button>
	</div>
</form>
```

The `$effect` watches `result`. When the server returns a successful result, `onDone(contact)` is called and the parent closes the dialog and refreshes the list.

## Step 7 — Try to break RLS (it won't budge)

Sanity check that RLS is doing its job. In Studio:

```sql
-- As postgres (superuser), try to insert a row with the *other* user's ID
insert into public.contacts (user_id, full_name)
values ('22222222-2222-2222-2222-222222222222', 'Should not work from app');
-- This *does* work in Studio (postgres bypasses RLS). Normal.

-- But from the app, trying to insert another user's row would fail.
-- Our handler always uses user.id from locals, so an attacker can't spoof user_id.
```

The defense: the remote function *never* takes `user_id` as input. The client can't lie about it. Whatever JWT is on the request determines `user_id` via `locals.user.id`.

## Verify

- `/contacts` renders with a header and an **+ New contact** button.
- Dialog opens/closes (Escape, backdrop, Cancel all work).
- Submitting creates a row owned by the signed-in user.
- Empty/invalid fields show inline errors.

## Common traps

- **Accepting `user_id` from the client.** Never. The server sets it from `locals.user`. This is the single most common RLS-bypass bug.
- **Empty string email stored as `''`.** Coerce `|| null` so "no email" is truly null.
- **Dialog without Escape/backdrop-close.** Users will curse you; keyboard accessibility is required.
